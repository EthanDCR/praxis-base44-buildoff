The Big Picture

This is a storm damage canvassing tool. The workflow is: find where hail hit → identify properties in that area → add them to a call list → work the list. Every part of the app feeds one of those steps.

The Frontend (storm-frontend/)

Built with React and Vite. TypeScript throughout. Three routes wired up in App.tsx:

/ → Storm Map (HailMap.tsx)
/leads → Call list management (Leads.tsx)
/speed-dial → Speed dial (SpeedDial.tsx)

Each page is a self-contained folder under src/pages/ with its own .tsx component and a .module.css file for scoped styles. CSS Modules mean the class names are auto-scoped per file — .card in Leads and .card in HailMap don't conflict.

Shared stuff lives in:

  • src/lib/base44.ts — creates the Base44 client (one line)
  • src/lib/xweather.ts — functions for fetching hail reports and storm cells from XWeather
  • src/lib/swath.ts — fetches from a separate swath API (currently less used)
  • src/components/Navbar/ — the top nav bar
Animations: The fade/blur entrance animations you see everywhere use Framer Motion (motion/react). The pattern is always the same: initial (blurred, offset) → animate (clear, in place), with a small delay to stagger items.

Storm Map Page (HailMap.tsx)

This is the main page. It has two main sections: a left sidebar for controls and a full-screen map.

The Map

Powered by MapLibre GL — an open-source WebGL map renderer. Think of it like Google Maps but you control the data layers. The base tiles (the actual map imagery) come from CartoDB (dark mode) or ArcGIS (satellite).

Two data layers are drawn on the map:

  • NOAA MRMS polygons — filled + outlined polygons showing where hail fell, sized by severity. These come from your Base44 database (processed by the pipeline).
  • XWeather Confirmed reports — colored dots from human spotters and storm reports. These are individual coordinate points, not polygons.

On top of those, XWeather MapsGL adds live weather overlays (radar, hail-size layer) via their SDK. This loads asynchronously after the base map is ready.

Click to Select a Property

Clicking anywhere on the map fires a reverse geocode request to Nominatim (OpenStreetMap's free geocoding service). It takes the lat/lon you clicked and returns a human-readable address. That address shows up in the sidebar's "Selected Property" section, where you can add it to a call list.

Filters

  • Date Range — filters both the MRMS polygons and XWeather reports to the last N days. Done client-side for MRMS (data is already loaded), API-side for XWeather.
  • Min Hail Size — hides anything below the chosen size threshold.

The Active List

The sidebar has a "Active List" dropdown. This is which call list you're currently adding properties to. You can create a new list or pick an existing one. When you click "+ Add to List," it creates a Target record in Base44 under that list.

Leads Page (Leads.tsx)

This is your call list management page. All data lives in Base44 — nothing is stored locally.

  • Switch List button (top right of the header) — dropdown to filter the view to a specific call list.
  • Active list name shows on the left of the header. "All Leads" means you're viewing everything.
  • Filter tabs — filter cards by status: All, Callback, New, Called, Inspection Set, Not Interested.
  • Progress bar — shows what % of the list has been dialed (anything that's not "New").
  • Cards — each card is a Target (a property/contact). Orange left-border = callback, blue = new. Called / sold / not interested go slightly faded.

The data is fetched once on mount and filtered client-side. No re-fetch when you switch lists or filters — it's all already in memory.

Data Sources

NOAA

MRMS MESH — Radar-derived hail polygons

MRMS (Multi-Radar Multi-Sensor) is NOAA's national radar network. MESH (Maximum Estimated Size of Hail) is a product that estimates the largest hail size at each point on the ground, derived from radar reflectivity. NOAA publishes this as GRIB2 files (a meteorological data format) on a public AWS S3 bucket, updated every 2 minutes.

Your Python pipeline downloads these files, composites a full day into a single "worst hail per location" grid, extracts polygons where hail exceeded certain thresholds, and stores them in Base44. These become the colored polygon shapes on the map.

XWeather

XWeather (AerisWeather) — Confirmed reports & live radar

XWeather is a commercial weather data provider. You use two things from them:

  • Storm Reports API — human-confirmed hail sightings from spotters, emergency managers, and NWS reports. These are the colored dots on the map. Filtered by size and date range.
  • MapsGL SDK — their JavaScript SDK that renders live radar and hail-size overlays directly onto the MapLibre map. This requires a client ID and secret.

API calls go through the Vite proxy (see below) to keep your credentials out of the browser.

OSM

Nominatim — Address search & reverse geocoding

Nominatim is OpenStreetMap's free geocoding service. The app uses it for two things: (1) the address search bar autocomplete, and (2) reverse geocoding when you click the map — turning lat/lon into a readable address. No API key required, but there's a usage policy (no heavy bulk use).

Base44

Base44 — Your database & backend

Base44 is a no-code backend platform. Instead of writing a Node/Python server and database schema, you define "entities" in Base44's dashboard and it gives you a REST API automatically. The SDK client in src/lib/base44.ts handles authentication.

Your three entities:

  • HailSwath — one record per polygon per day. Stores the GeoJSON geometry, hail size, and event date. Read by the map.
  • CallList — a named list (e.g. "Appleton WI July 2026"). Has a status: not started, in progress, completed, on hold.
  • Target — a property/contact inside a list. Has an address, contact info, status (new/called/callback/sold/not_interested), and notes.

The Hail Pipeline (hail-pipeline/)

This is a set of Python scripts you run manually (or could schedule) to pull fresh data. There are four scripts:

fetch_mrms.py
Downloads GRIB2 files from NOAA's public S3 bucket. Decompresses them. Skips files you already have (cached).
↓
process_mesh.py
Loads all the GRIB2 files for a day. Takes the maximum hail value at each grid cell across all time steps. Converts mm → inches, then traces polygon boundaries around hail threshold zones. Smooths the jagged raster edges into clean shapes. Outputs GeoJSON.
↓
push_to_base44.py
Takes the GeoJSON and POSTs each polygon as a HailSwath record in Base44.
↓
run.py
Orchestrates the above three. You run this one. Supports single-day or multi-day backfill.

Important: --step flag

NOAA publishes a new GRIB2 file every 2 minutes — that's 720 files per day. Processing all 720 gives you the most accurate storm-total composite. The --step 5 flag (which is the default for backfills) only uses every 5th file (144 files), making it 5× faster but potentially missing peak hail intensity in the skipped minutes.

For production quality runs, use --step 1. It takes longer but captures every storm cell correctly.

# Single day, full resolution, push to Base44:
python run.py --date 2026-07-27 --step 1

# Backfill last 30 days, full resolution, force re-push:
python run.py --days-back 30 --step 1 --force

# Test without pushing:
python run.py --date 2026-07-27 --step 1 --skip-push

Raw GRIB2 files are cached in hail-pipeline/data/raw/ (gitignored — they're large). Processed GeoJSON goes to hail-pipeline/data/output/.

Base44 — The Backend You Don't Have to Write

Normally a project like this would need a server (Node, Python, whatever) and a database (Postgres, MongoDB). Base44 replaces both. You define your data model in their dashboard, and they give you:

  • A REST API to create, read, update, delete records
  • Authentication (the appId key identifies your app)
  • Storage that persists across sessions

The SDK client (base44.entities.HailSwath.list()) is just a thin wrapper around those REST calls. Every entity you defined in Base44's dashboard becomes available as base44.entities.YourEntity.

Trade-off: Base44 is fast to build with but you're dependent on their platform. If you ever wanted to self-host, you'd need to export your data and wire up your own API.

The Vite Proxy — Hiding API Keys

API keys should never be in frontend JavaScript — anyone can open DevTools and read them. The Vite dev server has a proxy feature that lets the frontend make requests to /xweather-api/..., and Vite's server secretly replaces that with the real XWeather URL including the credentials. The browser never sees the actual key.

# What the frontend calls:
fetch('/xweather-api/stormreports/search?...')

# What Vite sends to XWeather (backend only):
https://api.aerisapi.com/stormreports/search?client_id=XXX&client_secret=YYY&...

This is configured in vite.config.ts. The keys themselves come from .env (which is gitignored).

Hail Size Color Scale

Both data layers (MRMS polygons and XWeather dots) use the same color scale:

< 0.75"
0.75" (penny)
1.0" (quarter)
1.25" (half dollar)
1.5" (ping pong)
1.75"
2.0"+ (golf ball)

Anything 1.0"+ (quarter size) is generally considered significant for property damage claims. 1.5"+ is where you see most roof damage.

Environment Variables

All secrets live in .env files (gitignored). The frontend ones are prefixed with VITE_ so Vite can inject them at build time.

# storm-frontend/.env
VITE_BASE44_APP_ID=your-app-id           # Which Base44 app to talk to
VITE_XWEATHER_CLIENT_ID=...            # XWeather MapsGL live overlays
VITE_XWEATHER_CLIENT_SECRET=...        # XWeather MapsGL live overlays
VITE_SWATH_API_KEY=...                 # Separate swath geometry API
VITE_XWEATHER_ID=...                   # Used by Vite proxy for server-side calls
VITE_XWEATHER_SECRET=...

# hail-pipeline/.env
BASE44_APP_ID=your-app-id
BASE44_API_KEY=your-api-key            # Server-side key for pushing data
Remember: The VITE_ prefix means these values get baked into the built JavaScript and are visible to anyone who downloads your site. That's fine for the app ID (it's not secret), but the XWeather credentials are protected by the proxy so they never reach the frontend bundle.
